- `GHSA-337j-9hxr-rhxg` (SSR constructor injection via

### Regla operativa

Si un controller expone un endpoint `GET/PUT/PATCH/DELETE /{id:guid}`
y el `{id}` representa un recurso del usuario (titular, cuenta,
extracto, conciliacion, lote, alerta, backup, exportacion, etc.), el
test xUnit a nivel de controller debe cubrir como minimo:

- empleado/gerente con `PermisosUsuario` ajeno al id -> 403 (`ForbidResult`).
- titular/cuenta soft-deleted -> 403 o 404 segun contrato.
- admin -> siempre 200/204 (bypass intencional).

Esto bloquea el patron "controller nuevo con scope olvidado" que es
el vector real de IDOR en una refactorizacion.

### Nota sobre el autoprefixer

`lightningcss` (auto-prefixer integrado en Vite 8) duplica la
declaracion `-webkit-mask:var(--logo-mask) ...` cuando el valor es
`var()`: la salida final tiene 3 referencias por selector en lugar
de las 2 del codigo fuente. Es inocuo (los navegadores usan la ultima
declaracion que gana la cascada) y suma ~140 bytes al bundle CSS.
No es regresion: la version anterior con `url('/logos/...')` tampoco
duplicaba porque `url()` no dispara el caso del prefijo.
